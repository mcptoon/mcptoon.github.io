为什么「工具太多」这么费 token

MCP 按设计是无状态的。客户端无法预知你会用哪个工具，于是每一次请求都把所有已连接工具的 完整入参 Schema 一起发给模型。一个写得清楚点的工具，光 JSON 就 300–600 token。几十个服务器、上百个 工具乘起来，光「工具清单」这一项，就能在对话还没开始前吃掉几万 token。

这笔钱每一轮都要付。它挤占你真正的上下文窗口——代码、文档、前面的对话——而且你每加一个 服务器，它都悄悄变大。

怎么判断你是不是这个问题

  • 加了服务器之后，助手「忘事」明显变快。
  • 以前装得下的任务，现在动不动就顶到上下文上限。
  • 你没写更长的提示词，账单却涨了。
  • 你连着的工具超过约 30 个。

正解：用名字索引代替完整 Schema

mcptoon 让你所有工具都保持安装，但只把一份紧凑的名字索引发给模型。当模型真的要用某个 工具时，再去取那一个工具的真实 Schema 并调用。工具一个不少，模型不再为没用到的工具付费。

常见问题

MCP 工具数量有硬上限吗？

没有固定数字——上限是你的上下文窗口。每个工具的 Schema 每轮都计费，所以实际天花板是「多少份 Schema 塞得下、又不挤掉你真正要干的活」。

减少 MCP token 一定要删工具吗？

不用。这正是索引的意义：工具全留着，只为真正调用的那一个付 Schema 的钱。删工具是那种「下周还得 加回来」的临时办法。

Claude Code、Cursor、Codex、opencode 都能用吗？

能。mcptoon 面向 103+ 款桌面与终端 Agent，零配置安装。当前清单见 README。
