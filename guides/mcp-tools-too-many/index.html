Why "too many tools" costs so much

MCP is stateless by design. A client cannot know which tool you will need, so it sends the model the complete input schema of every connected tool, on every request. A single well-documented tool is often 300–600 tokens of JSON. Multiply by a hundred tools across a handful of servers and the tool list alone can swallow tens of thousands of tokens before the conversation even starts.

That cost is paid every turn. It crowds out your actual context window — the code, the docs, the earlier messages — and it grows silently every time you add a server.

How to tell if this is your problem

  • The assistant "forgets" earlier messages sooner after you add servers.
  • You hit context limits on tasks that used to fit.
  • Your bill went up without you writing longer prompts.
  • You have more than ~30 tools connected.

The fix: a name index instead of full schemas

mcptoon keeps every tool installed but sends the model only a compact name index. When the model actually needs a tool, it asks for that one tool's real schema and calls it. You keep all your tools; the model stops paying for the ones it is not using.

mcptoon manifest          # the compact name index the model sees

FAQ

Is there a hard limit on how many MCP tools I can have?

No fixed number — the limit is your context window. Each tool's schema is billed every turn, so the practical ceiling is "however many schemas fit without crowding out your real work."

Do I have to delete tools to reduce MCP token usage?

No. That is the point of an index: you keep every tool and only pay for the schema of the one you actually call. Deleting tools is the temporary fix that forces you to re-add them later.
